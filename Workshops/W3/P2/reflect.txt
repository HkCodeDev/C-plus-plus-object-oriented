1. What is the reason for defining the class objects outside the class definition?:
because static members m_smallestItem and m_largestItem
are defined outside of class definition.
static members are shared among instances of a class,
So it is required for them be allocated once, 
this method makes sure this happens.
for example in Collenction.h:
template <typename T, unsigned C>
T Collection<T, C>::m_smallestItem = 9999;
this is static member initilization
another reason is seperating the implementation from the
interface, which makes it easy to read.
2.What is the reason for specializing the definition of m_smallestItem and m_largestItem objects for Book and 10:
template <>
Book Collection<Book, 10>::m_smallestItem = Book("", 1, 10000);
When specializing Book with capacity of 10,
we make sure that m_smallestItem and m_largestItem
are initilized to meaningful values
also by specializing we avoid any type difficulty
template <>
Book Collection<Book, 72>::m_smallestItem = Book("", 1, 10000);

template <>
Book Collection<Book, 72>::m_largestItem = Book("", 10000, 1);
3.m_smallestItem and m_largestItem objects are also initialized for Book and 72. Is this initilization necessary? Why?
yes, and the reason is making sure the collection doesn't have an unexpected behavior
and also we have meaningful comparison, too know
what large and small extrems look like in book
without these the code might use values
such as 9999 or -9999 which doesn't make sense

The operator[] in Collection.h is a mutator and it 
returns a reference to an element in the collection, allowing change to that element. 
If it was a query, it would return a constant value, which means changing it is not possible.
when it's a mutator, it allows derived classes(OrderedCollection.h) to change the elements directly, and can
reorder them: 
collection.h:
    template <typename T, unsigned C>
    T& Collection<T, C>::operator[](unsigned index) {
        return m_items[index];
    }
